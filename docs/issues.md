# PhotoPrivacy GitHub Issues 设计

以下 Issue 按依赖顺序排列。每个 Issue 对应一个可独立检查、测试和合并的工作单元。

## Issue 1：实现带边界检查的二进制读取器

**建议标签：** `基础设施`、`安全`、`优先级：高`

### 背景

图像文件是不可信的二进制输入。解析 JPEG、PNG、WebP 和 Exif 时，不能直接相信文件声明的长度与偏移，否则可能发生越界读取、整数溢出或异常终止。

### 工作内容

- 定义统一读取错误，记录错误位置、期望长度和剩余长度。
- 实现安全读取 `u8`、大端/小端 `u16` 和 `u32`。
- 实现带边界检查的切片、跳过和剩余长度查询。
- 为异常偏移、截断输入和超大长度声明设置限制。

### 验收标准

- 所有读取操作在访问数据前完成边界检查。
- 正常、大端、小端、空输入、末尾读取和截断输入均有测试。
- 恶意长度不会导致崩溃、死循环或巨量内存分配。
- `moon check` 与 `moon test` 通过。

## Issue 2：定义统一的图像信息、元数据与隐私风险模型

**建议标签：** `设计`、`核心功能`、`优先级：高`

### 背景

不同图像格式使用不同的段、块和标签。界面与 CLI 需要一套与具体格式无关的数据模型，统一展示图像属性、元数据、风险和不受支持的信息。

### 工作内容

- 定义 `ImageInfo`、`MetadataItem`、`PrivacyRisk` 和 `ParseDiagnostic`。
- 区分显示必需信息、可移除元数据和未知数据。
- 为 GPS、拍摄时间、设备、软件、作者和注释定义风险分类。
- 设计稳定的文本或 JSON 输出形式。

### 验收标准

- JPEG、PNG 和 WebP 结果可以映射到同一模型。
- 未知字段不会被静默丢弃，并能在报告中定位。
- 风险等级和判定理由可被用户理解。
- 公共 API 有文档与测试。

## Issue 3：实现 JPEG 段结构解析与基础属性读取

**建议标签：** `JPEG`、`解析器`、`优先级：高`

### 工作内容

- 校验 SOI，并遍历 APPn、COM、SOF、SOS 和 EOI 等标记。
- 正确处理无长度标记、填充字节和熵编码数据。
- 从 SOF 读取宽度、高度、位深与分量数。
- 建立段清单并标记 APP1、APP13、COM 等潜在元数据。

### 验收标准

- 能解析最小 JPEG 和包含未知 APP 段的 JPEG。
- 能拒绝非法长度、截断段、缺失 SOI/EOI 等输入。
- 不解码或修改 JPEG 压缩像素数据。
- 每类边界情况都有自动测试。

## Issue 4：实现 Exif/TIFF IFD 元数据解析

**建议标签：** `Exif`、`元数据`、`优先级：高`

### 工作内容

- 解析 TIFF 字节序、魔数、IFD 偏移和条目。
- 支持常见数值、ASCII、Rational 与数组类型。
- 解析 IFD0、Exif IFD 和 GPS IFD 的常见标签。
- 对未知标签保留标签号、类型、数量和原始位置。
- 对循环、越界偏移和异常条目数量设置限制。

### 验收标准

- 支持大端与小端 Exif 样例。
- 能输出设备、时间、方向、软件和 GPS 等常见信息。
- 恶意偏移、循环引用和截断输入不会导致崩溃。
- 测试样例来源和许可记录清楚。

## Issue 5：实现 JPEG 元数据清理与二次验证

**建议标签：** `JPEG`、`清理器`、`隐私`、`优先级：高`

### 工作内容

- 删除 Exif/XMP、IPTC、COM 和明确不需要的 APP 段。
- 保留解码 JPEG 所需结构和压缩扫描数据。
- 生成删除项、保留项和节省字节数报告。
- 对方向与色彩配置可能造成的显示变化给出提示。
- 使用独立的第二次解析检查清理结果。

### 验收标准

- 清理后的文件能够再次解析并正常显示。
- 原始压缩扫描数据在无损结构清理模式下保持不变。
- 已支持的隐私元数据在复检中全部消失。
- 重复清理同一文件得到相同结果。

## Issue 6：实现 PNG 块检查、CRC 校验与元数据清理

**建议标签：** `PNG`、`解析器`、`清理器`、`优先级：中`

### 工作内容

- 解析 PNG 签名、块长度、块类型、数据和 CRC。
- 读取 IHDR，并识别文本、时间、Exif、色彩和动画块。
- 移除 `eXIf`、`tEXt`、`zTXt`、`iTXt`、`tIME` 等策略指定块。
- 保留关键块、透明度、必要色彩信息和 APNG 动画结构。

### 验收标准

- 能报告未知块以及 CRC 错误。
- 不删除图像解码必需的关键块。
- 清理后 CRC 和块顺序合法，文件可以再次解析。
- 静态 PNG、带文本 PNG 和 APNG 均有测试。

## Issue 7：实现 WebP RIFF 检查与元数据清理

**建议标签：** `WebP`、`解析器`、`清理器`、`优先级：中`

### 工作内容

- 校验 RIFF/WEBP 头并遍历 FourCC 块。
- 识别 VP8、VP8L、VP8X、ALPH、ANIM、ANMF、EXIF、XMP 与 ICCP。
- 清理 EXIF/XMP，修正 RIFF 长度与 VP8X 元数据标志。
- 保留透明度和动画相关结构。

### 验收标准

- 支持有损、无损、透明和动画 WebP 的结构报告。
- 奇数长度块的填充与 RIFF 总长度处理正确。
- 清理后文件能够复检，动画和透明度不被破坏。

## Issue 8：构建本地 WebAssembly 拖放界面

**建议标签：** `WebAssembly`、`界面`、`演示`、`优先级：中`

### 工作内容

- 支持拖放和文件选择，并显示本地预览。
- 将 `ArrayBuffer` 传入 MoonBit/Wasm 检查接口。
- 展示真实格式、图像属性、元数据、风险和诊断。
- 调用清理接口并通过 Blob 下载输出文件。
- 明确展示“本地处理，不上传图片”的状态。

### 验收标准

- 页面无需后端、账号或远程图像处理 API。
- JPEG、PNG、WebP 的选择、报告、清理和下载流程可复现。
- 不受支持格式给出明确说明，不生成可能损坏的输出。
- 浏览器对象 URL 使用后被释放，错误不会泄露原始内容。
